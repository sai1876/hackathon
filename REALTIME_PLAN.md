# AegisGrid: continuously running synthetic traffic plan

## Outcome

A live-updating traffic control workspace on real Hyderabad road geometry. Traffic observations are synthetic and causally generated by a server simulation, not arbitrary changing counters. Google provider references and AI explanations retain separate labels.

## Implementation sequence

1. **Dataset preparation:** use the supplied OSM exports and existing Mallampet/Bachupally prepared roads. Derive a bounded connected road network. Generate documented hourly demand profiles and initial vehicle loads with a fixed random seed. Preserve original datasets.
2. **Traffic engine:** advance a shared backend clock; conserve vehicle stock across road transfers; limit flow by road capacity, downstream space and signal state; compute queue size, speed, occupancy, delay and throughput. Make pause, resume, time scaling, weather and demand settings server commands.
3. **Operator actions:** road incidents reduce capacity or close links; signal priority and diversions change service and inflow; action history records before/after model values. Synthetic ambulance requests still require approval; approved vehicles move automatically while the simulation runs, prepare upcoming junctions, and release passed junctions.
4. **Google Maps APIs:** add a Google Maps JavaScript map with TrafficLayer for live Google traffic. Reuse one map instance and toggle layers without recreating it. Keep the existing MapLibre fallback. TrafficLayer cannot be attached to MapLibre. Show Google live traffic and synthetic model traffic as separately labeled selectable views so simulated closures never masquerade as changes in Google observations. Use Routes traffic-aware ETA references only when numerical provider comparison is needed; TrafficLayer is visualization, not a per-road numeric data feed. Preserve NetworkX as the incident-aware operational routing engine. Use separate restricted browser and server API keys.
5. **Groq and Gemini:** Groq explains structured synthetic traffic evidence; Gemini offers a second opinion/fallback. Validate evidence IDs and action choices against deterministic candidates. Neither model moves vehicles or operates signals directly.
6. **Usage and persistence:** record attempted provider calls atomically before sending; enforce conservative configurable monthly ceilings; show provider status and counters. Store local checkpoints and counters on disk. These are this installation's counters, not account-wide invoices or guaranteed free quotas.
7. **Interface:** color actual road segments by simulated speed/occupancy; display representative moving vehicle tracers, signal states, queue trends, actionable road inspection, provenance and the event journal. Keep corridor requests on `/ambulance` and decisions on `/traffic`.
8. **Verification:** test vehicle conservation, queue buildup/recovery, controls, ambulance approval gates, action effects, provider fallback, quota concurrency and restart persistence. Build and lint the frontend; verify the running API and live clock.

## Keys to supply locally

Edit `D:\aegisgrid\backend\.env` without changing existing Supabase entries:

```dotenv
GOOGLE_MAPS_API_KEY=
GROQ_API_KEY=
GEMINI_API_KEY=
GROQ_MODEL=llama-3.3-70b-versatile
GEMINI_MODEL=gemini-2.5-flash
GOOGLE_ROUTES_HARD_LIMIT=100
GROQ_HARD_LIMIT=300
GEMINI_HARD_LIMIT=100
```

Empty keys leave that provider unavailable while the synthetic engine works. The initial application caps are conservative request ceilings, not provider free-tier claims. Add the keys in the local file, then restart the backend. The UI will report whether each provider is configured and whether a request succeeded. Never paste credentials into chat or any `NEXT_PUBLIC_` variable.

## Google map browser configuration

The Google map also needs a **separate browser key**, intentionally visible to the browser and restricted to Maps JavaScript API and approved HTTP referrers (localhost during development, the deployment domain later). Server keys for Routes, Groq, Gemini and Supabase remain backend-only.

Add this to `D:\aegisgrid\web\.env.local` when creating the browser key:

```dotenv
NEXT_PUBLIC_GOOGLE_MAPS_BROWSER_KEY=
```

## Verified billing facts and implementation consequences

- TrafficLayer does not introduce a separate traffic-layer charge; the underlying Dynamic Maps load is billable under the applicable map SKU. Layer toggles, panning and zooming on an existing loaded map do not create new map loads. Avoid repeated map initialization during React renders or simulation ticks.
- The recurring USD 200 credit ended on February 28, 2025. From March 1, 2025, per-SKU monthly free usage caps replaced it. Do not budget using the old credit.
- The current India price list shows 70,000 free monthly Dynamic Maps billable events for eligible India pricing. Eligibility and the account's already-used quota must be checked; location alone is not proof of pricing eligibility.
- Frontend map-initialization counts are advisory observations, not authoritative Google billing counters. Configure Google Cloud quotas/restrictions as well as application limits. Routes API calls are separately counted and not needed merely to show TrafficLayer.
- TrafficLayer refreshes frequently, not instantaneously, and does not expose raw numerical traffic observations for the synthetic engine. Synthetic queue/flow state comes from the model; numerical Google comparisons come from Routes.

## Boundaries

This is a synthetic operations simulator, not live Hyderabad telemetry or real signal actuation. Lane counts, controller placement and demand are modeling assumptions unless verified datasets are supplied. The first simulation area is the supplied Mallampet/Bachupally road network; coverage can expand through additional prepared data. Local SQLite persistence requires durable disk if later hosted. Authentication and trusted operator identity remain separate work.
